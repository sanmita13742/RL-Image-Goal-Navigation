# MINav LiDAR Safety Gate

A lightweight, minimal-dependency safety gate for the AgileX Ranger Mini V3 during MINav offline RL dataset collection.

## Purpose
The Safety Gate is designed to intercept velocity commands generated by the MINav pink noise exploration policy (`/minav/cmd_vel`), check them against the raw point cloud from the RoboSense LiDAR (`/rslidar_points`), and publish a safe command to the Ranger base (`/cmd_vel`).

It applies a conservative 3D geometric envelope to detect obstacles directly in front of the robot and suppresses forward motion if an obstacle is within the configured stop distance.

**Important:** This safety gate *fails closed*. If the point cloud becomes stale, forward motion is blocked.

## Topics
- **Subscribes to:**
  - `/minav/cmd_vel` (`geometry_msgs/msg/Twist`) — Raw commands from MINav.
  - `/rslidar_points` (`sensor_msgs/msg/PointCloud2`) — Raw point cloud from LiDAR.
- **Publishes to:**
  - `/cmd_vel` (`geometry_msgs/msg/Twist`) — Safe commands to the Ranger base.
  - `/safety_gate/obstacle_distance` (`std_msgs/msg/Float32`) — Diagnostic distance to closest obstacle.
  - `/safety_gate/blocked` (`std_msgs/msg/Bool`) — Diagnostic blocked state.
  - `/safety_gate/point_count` (`std_msgs/msg/Int32`) — Number of points inside the safety envelope.
  - `/safety_gate/cloud_age` (`std_msgs/msg/Float32`) — Age of the last received point cloud.

## Parameters
Parameters are configured in `realworld/configs/realworld_pipeline.yaml` under the `safety_gate` section:

- `input_cmd_topic`: Topic to listen for MINav commands (default: `/minav/cmd_vel`)
- `output_cmd_topic`: Topic to publish safe commands (default: `/cmd_vel`)
- `lidar_topic`: Topic for raw LiDAR (default: `/rslidar_points`)
- `front_min_x`: Minimum X distance (m) to filter out the robot chassis (default: `0.15`)
- `front_max_x`: Maximum X distance (m) to check for obstacles (default: `0.8`)
- `lateral_min_y` / `lateral_max_y`: Lateral bounds of the safety envelope (default: `-0.4` to `0.4`)
- `min_z`: Minimum Z height (m) to filter out the ground (default: `-0.2`)
- `max_z`: Maximum Z height (m) to ignore ceiling or high overhangs (default: `0.5`)
- `stop_distance`: Distance (m) at which forward motion is suppressed (default: `0.5`)
- `minimum_points`: Minimum number of points required to confirm an obstacle, mitigating noise (default: `10`)
- `cloud_timeout_s`: Time (s) before the safety gate fails closed (default: `1.0`)

## Safety Logic
1. Filters the point cloud using the configured 3D bounding box (`front_min_x` to `front_max_x`, etc.).
2. Counts the number of points in the box.
3. If the count is >= `minimum_points`, an obstacle is detected.
4. The obstacle distance is calculated using the 5th percentile of the X coordinates (to avoid false positives from a single noise point).
5. If the distance < `stop_distance`, the state becomes BLOCKED.
6. When a command arrives from `/minav/cmd_vel`, if the state is BLOCKED and the command commands forward motion (`linear.x > 0`), the forward velocity is zeroed.
7. Safe commands are published to `/cmd_vel`.

*Note: Lateral and angular commands are intentionally NOT altered, allowing the policy to crab-walk or spin away from obstacles without interference.*

## How to Test Safely
Before running with the robot armed, test the safety node in isolation.

**1. Launch the LiDAR:**
```bash
ros2 launch ranger_bringup open_rslidar.launch.py
```

**2. Run the Safety Gate:**
```bash
python3 realworld/scripts/run_safety_gate.py --config realworld/configs/realworld_pipeline.yaml
```

**3. Verify Telemetry:**
Place an object (e.g., a cardboard box) in front of the LiDAR.
```bash
ros2 topic echo /safety_gate/blocked
ros2 topic echo /safety_gate/obstacle_distance
```

**4. Test with MINav (Dry Run):**
Run the exploration script in dry-run mode (without `--arm`). MINav will publish to `/minav/cmd_vel`. Verify that the safety node intercepts and suppresses forward commands when an obstacle is present.
