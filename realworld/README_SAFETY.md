# MINav LiDAR Safety Gate

A lightweight, minimal-dependency safety gate for the AgileX Ranger Mini V3 during MINav offline RL dataset collection.

## Purpose
The Safety Gate is designed to intercept velocity commands generated by the MINav pink noise exploration policy (`/minav/cmd_vel`), check them against the raw point cloud from the RoboSense LiDAR (`/rslidar_points`), and publish a safe command to the Ranger base (`/cmd_vel`).

Because the Ranger Mini V3 is a holonomic platform capable of omnidirectional movement (crab-walking, diagonal, reverse), this safety gate uses a **Chassis-Aware Command-Direction** approach. 

The safety gate dynamically calculates the exact swept footprint of the physical robot chassis (751mm x 600mm) based on the intended movement vector. It ensures it blocks motion only if an obstacle intersects this exact physical corridor.

**Important:** This safety gate *fails closed*. If the point cloud becomes stale, translational motion is immediately blocked.

## Topics
- **Subscribes to:**
  - `/minav/cmd_vel` (`geometry_msgs/msg/Twist`) — Raw commands from MINav.
  - `/rslidar_points` (`sensor_msgs/msg/PointCloud2`) — Raw point cloud from LiDAR.
- **Publishes to:**
  - `/cmd_vel` (`geometry_msgs/msg/Twist`) — Safe commands to the Ranger base.
  - `/safety_gate/obstacle_distance` (`std_msgs/msg/Float32`) — Diagnostic distance to closest relevant obstacle *from the chassis edge* in the command path.
  - `/safety_gate/blocked` (`std_msgs/msg/Bool`) — Diagnostic blocked state.
  - `/safety_gate/point_count` (`std_msgs/msg/Int32`) — Number of points inside the dynamic safety corridor.
  - `/safety_gate/cloud_age` (`std_msgs/msg/Float32`) — Age of the last received point cloud.

## Parameters
Parameters are configured in `realworld/configs/realworld_pipeline.yaml` under the `safety_gate` section:

- `input_cmd_topic`: Topic to listen for MINav commands (default: `/minav/cmd_vel`)
- `output_cmd_topic`: Topic to publish safe commands (default: `/cmd_vel`)
- `lidar_topic`: Topic for raw LiDAR (default: `/rslidar_points`)
- `robot_length`: Overall length of the Ranger Mini footprint in meters (default: `0.751`)
- `robot_width`: Overall width of the Ranger Mini footprint in meters (default: `0.60`)
- `safety_margin`: Extra buffer space around the footprint in meters (default: `0.1`)
- `lidar_offset_x`: X offset of the LiDAR from the center of the chassis (default: `0.0508`)
- `lidar_offset_y`: Y offset of the LiDAR from the center of the chassis (default: `0.0`)
- `blindspot_radius`: Minimum radial distance (m) to filter out the robot chassis from the point cloud (default: `0.15`)
- `min_command_speed`: Minimum translational speed (m/s) to trigger direction checking (default: `0.01`)
- `min_z`: Minimum Z height (m) to filter out the ground (default: `-0.2`)
- `max_z`: Maximum Z height (m) to ignore ceiling or high overhangs (default: `0.5`)
- `stop_distance`: Distance (m) *from the edge of the chassis* at which translational motion is suppressed (default: `0.5`)
- `minimum_points`: Minimum number of points required to confirm an obstacle, mitigating noise (default: `10`)
- `cloud_timeout_s`: Time (s) before the safety gate fails closed (default: `1.0`)

## Safety Logic
1. Filters the point cloud vertically (`min_z`, `max_z`) and radially (`blindspot_radius`), caching it.
2. When a command arrives, if the LiDAR cloud is older than `cloud_timeout_s`, it fails closed (zero translation).
3. If the speed is extremely slow (`< min_command_speed`), the command is passed.
4. Otherwise, normalizes the velocity into a direction vector (`dir_x`, `dir_y`).
5. Transforms LiDAR points by `lidar_offset` to align with the chassis center.
6. Projects the points onto the direction vector to find their `parallel` distance and `perpendicular` offset.
7. Dynamically calculates the physical bounds:
   - `max_perp = (Length/2)*abs(dir_y) + (Width/2)*abs(dir_x)`
   - `max_para = (Length/2)*abs(dir_x) + (Width/2)*abs(dir_y)`
8. A point is an obstacle if:
   - It's in front of the robot: `parallel > max_para`
   - It's within the stop distance: `parallel <= max_para + stop_distance`
   - It's within the physical corridor: `abs(perpendicular) <= max_perp + safety_margin`
9. If the number of relevant points is `>= minimum_points`, the path is blocked.
10. If blocked, `linear.x` and `linear.y` are zeroed out.

## Examples
- **Forward:** `max_perp` evaluates to half the robot's width (0.3m). Only obstacles directly in front of the 0.6m wide footprint are checked.
- **Left (Crab walk):** `max_perp` evaluates to half the robot's length (0.3755m). Only obstacles to the left of the 0.751m long footprint are checked.
- **Diagonal:** `max_perp` mathematically expands to project the exact cross-section of the rectangular chassis onto the diagonal path.

## How to Test Safely
Before running with the robot armed, test the safety node in isolation.

**1. Launch the LiDAR:**
```bash
ros2 launch ranger_bringup open_rslidar.launch.py
```

**2. Run the Safety Gate:**
```bash
python3 realworld/scripts/run_safety_gate.py --config realworld/configs/realworld_pipeline.yaml
```

**3. Test with Teleop (Dry Run):**
Use a teleop node publishing to `/minav/cmd_vel`. Move an obstacle around the robot and try commanding towards and away from it. Verify that commands *towards* the obstacle are zeroed, while commands *away* are passed.
