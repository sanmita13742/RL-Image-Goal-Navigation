# MINav LiDAR Safety Gate

A lightweight, minimal-dependency safety gate for the AgileX Ranger Mini V3 during MINav offline RL dataset collection.

## Purpose
The Safety Gate is designed to intercept velocity commands generated by the MINav pink noise exploration policy (`/minav/cmd_vel`), check them against the raw point cloud from the RoboSense LiDAR (`/rslidar_points`), and publish a safe command to the Ranger base (`/cmd_vel`).

Because the Ranger Mini V3 is a holonomic platform capable of omnidirectional movement (crab-walking, diagonal, reverse), this safety gate uses a **Command-Direction Based** approach. The safety corridor dynamically aligns with the intended movement vector, ensuring it blocks motion only if an obstacle is directly in the robot's intended path.

**Important:** This safety gate *fails closed*. If the point cloud becomes stale, translational motion is blocked.

## Topics
- **Subscribes to:**
  - `/minav/cmd_vel` (`geometry_msgs/msg/Twist`) — Raw commands from MINav.
  - `/rslidar_points` (`sensor_msgs/msg/PointCloud2`) — Raw point cloud from LiDAR.
- **Publishes to:**
  - `/cmd_vel` (`geometry_msgs/msg/Twist`) — Safe commands to the Ranger base.
  - `/safety_gate/obstacle_distance` (`std_msgs/msg/Float32`) — Diagnostic distance to closest relevant obstacle in the command path.
  - `/safety_gate/blocked` (`std_msgs/msg/Bool`) — Diagnostic blocked state.
  - `/safety_gate/point_count` (`std_msgs/msg/Int32`) — Number of points inside the dynamic safety corridor.
  - `/safety_gate/cloud_age` (`std_msgs/msg/Float32`) — Age of the last received point cloud.

## Parameters
Parameters are configured in `realworld/configs/realworld_pipeline.yaml` under the `safety_gate` section:

- `input_cmd_topic`: Topic to listen for MINav commands (default: `/minav/cmd_vel`)
- `output_cmd_topic`: Topic to publish safe commands (default: `/cmd_vel`)
- `lidar_topic`: Topic for raw LiDAR (default: `/rslidar_points`)
- `blindspot_radius`: Minimum radial distance (m) to filter out the robot chassis (default: `0.15`)
- `corridor_half_width`: Half-width of the dynamic safety corridor (default: `0.4`)
- `min_command_speed`: Minimum translational speed (m/s) to trigger direction checking (default: `0.01`)
- `min_z`: Minimum Z height (m) to filter out the ground (default: `-0.2`)
- `max_z`: Maximum Z height (m) to ignore ceiling or high overhangs (default: `0.5`)
- `stop_distance`: Distance (m) at which translational motion is suppressed (default: `0.5`)
- `minimum_points`: Minimum number of points required to confirm an obstacle, mitigating noise (default: `10`)
- `cloud_timeout_s`: Time (s) before the safety gate fails closed (default: `1.0`)

## Safety Logic
1. Filters the point cloud vertically (`min_z`, `max_z`) and radially (`blindspot_radius`), caching it.
2. When a command arrives, computes the planar speed (`sqrt(vx^2 + vy^2)`).
3. If the speed is extremely slow (`< min_command_speed`), the command is passed.
4. Otherwise, normalizes the velocity into a direction vector (`dir_x`, `dir_y`).
5. Projects the cached LiDAR points onto this vector to find their `parallel` distance and `perpendicular` offset.
6. A point is relevant if `parallel > 0`, `parallel <= stop_distance`, and `abs(perpendicular) <= corridor_half_width`.
7. If the number of relevant points is `>= minimum_points`, the path is blocked.
8. If blocked, `linear.x` and `linear.y` are zeroed out (suppressing translation). Angular velocity is left unchanged.
9. If the LiDAR cloud is older than `cloud_timeout_s`, it fails closed (zero translation).

## Examples
- **Forward (vx>0, vy=0):** Corridor points straight ahead. An obstacle in front blocks it. Obstacle behind is ignored.
- **Backward (vx<0, vy=0):** Corridor points backward. Obstacle behind blocks it. Obstacle in front is ignored.
- **Left (vx=0, vy>0):** Corridor points left (crab walk). Obstacle to the left blocks it.
- **Right (vx=0, vy<0):** Corridor points right. Obstacle to the right blocks it.
- **Diagonal (vx>0, vy>0):** Corridor points diagonally front-left. Only obstacles front-left block it.

## How to Test Safely
Before running with the robot armed, test the safety node in isolation.

**1. Launch the LiDAR:**
```bash
ros2 launch ranger_bringup open_rslidar.launch.py
```

**2. Run the Safety Gate:**
```bash
python3 realworld/scripts/run_safety_gate.py --config realworld/configs/realworld_pipeline.yaml
```

**3. Test with Teleop (Dry Run):**
Use a teleop node publishing to `/minav/cmd_vel`. Move an obstacle around the robot and try commanding towards and away from it. Verify that commands *towards* the obstacle are zeroed, while commands *away* are passed.
